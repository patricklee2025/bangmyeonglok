# WP-03 · ⏳ D-day 마을 (`dday`)

| 항목 | 값 |
|---|---|
| 브랜치 | `wp/03-dday` · 선행: WP-00c (WP-01과 독립) · 마감 M1 |
| 매니페스트 | pages `guest village` · phases `pre` · simple ✓ · liveSafe ✗ |
| 허락된 파일 | `public/js/features/dday/**` · `tests/features/dday.mjs` · `docs/guide/dday.md` · 매니페스트 줄 · STATUS/CHANGELOG |
| 데이터 | 없음 (코어 하객 목록만 사용) |

## 1. 목적
결혼식 전(사전 입주 기간)에 마을을 열어 본 하객이 "아직 준비 중인 결혼식 마을"을 보게 한다.
남은 날짜에 따라 마을 공사가 조금씩 진행되고, 입주한 하객들이 미리 돌아다닌다. 다시 와 볼 이유를 만든다.

## 2. 시나리오
| # | 기기 | 흐름 |
|---|---|---|
| S1 | 폰 (입주 후 "마을 구경하기") | 마을 + 상단 칩 "D-123 · 입주민 18명" + 제단의 D-day 표지판 + 공사 소품 · 내 캐릭터 금색 링(코어) |
| S2 | 노트북/TV (청첩장 모임 등) | HUD tl 존 패널 "결혼식까지 D-123 · 2027.04.10 (토) · 입주민 18명" |
| S3 | 하객 페이지 환영 화면 | 환영 슬롯 order 1: 작은 칩 "💒 결혼식까지 D-123" |
| S4 | D-1 | 표지판·칩 "내일 만나요! 🎉", 공사 소품 전부 사라지고 깃발 장식 |
| S5 | 페이즈가 live가 되는 순간 (06:00) | 기능 자동 dispose → 소품·HUD 사라짐 (페이즈 게이트) |

## 3. 공사 단계 (남은 일수 n = `ceil((liveStart - now) / 86400000)`)

| n | 단계 | 소품 (코드로 그린 픽셀 소품, `ctx.v.addProp`) |
|---|---|---|
| > 60 | 0 터 닦기 | 제단 앞 비계(scaffold) · 나무 상자 3개(한옥 마당) · "🚧 공사 중" 나무 표지판 |
| 31–60 | 1 기둥 세우기 | 비계는 제단 오른쪽만 · 상자 2개 · 사다리 |
| 8–30 | 2 장식 달기 | 비계 없음 · 상자 1개 · 광장 위 깃발 줄(overhead 층) |
| 2–7 | 3 마무리 | 깃발 줄 + 화분 4개(카펫 양옆) |
| 1 | 4 준비 완료 | 깃발 줄 + 화분 + "내일 만나요" 현수막(배너 소품 옆) |

- 단계는 부팅 때 계산 + 10분마다 재계산(자정 넘김). 단계 바뀌면 소품 교체.
- 소품 위치는 `ctx.v.Z` 기준 (제단 `altar`, 마당 `yard`, 카펫 `carpet`, 광장 `plaza`). **걷는 길을 막지 않는 자리**(walk 그리드는 코어 소유라 바꿀 수 없음 → 주민이 소품을 통과해 보일 수 있음: 소품은 길 가장자리·장식 위주로 배치).
- D-day 표지판: 제단 왼쪽 앞 나무 표지판 소품 + 숫자는 `onOverlay('under-tags')`로 그림 (월드에 글자 금지).

## 4. UX
| 위치 | 내용 |
|---|---|
| TV HUD `tl` | 패널: `dday_hud_title` / 큰 숫자 `D-{n}` / 날짜 / `dday_residents` |
| 폰 HUD `tc` | 칩 한 줄: `D-{n} · 입주민 {r}명` (탭하면 아무 일 없음) |
| 하객 환영 슬롯 order 1 | 칩 `dday_welcome` |

레벨 패널(코어)은 그대로 둠 — pre 기간에도 하객 수 레벨업 연출은 그대로 즐거움.

## 6. 엣지 케이스
- 시계가 틀린 폰: 그냥 그 폰 시각 기준 (중요하지 않음). 페이즈 강제 `?phase=pre`로 결혼식 뒤에 열면 n ≤ 0 → "D-day" 대신 0으로 표시하지 말고 단계 4 + `dday_tomorrow`.
- 하객 0명: 입주민 0명 표시, 마을은 신랑·신부만.
- 밤(코어 자동): 소품도 코어 조명 아래 자연스럽게 (조명 소스 추가 금지).

## 7. 수용 기준 → `tests/features/dday.mjs` (Playwright `page.clock.setFixedTime`으로 날짜 고정)
| # | 기준 |
|---|---|
| A1 | S1–S8 공통 (데이터 없음) |
| A2 | 시계를 **현지 정오**로 고정 (자정·UTC 날짜만 쓰면 경계에서 하루가 어긋남 — 예: `2027-04-09`는 UTC 자정 = 4/8 저녁 8시라 D-2가 됨):<br>`2026-12-01T12:00:00-05:00` → D-130 단계 0 · `2027-02-15T12:00:00-05:00` → D-54 단계 1 · `2027-03-20T12:00:00-04:00` → D-21 단계 2 · `2027-04-05T12:00:00-04:00` → D-5 단계 3 · `2027-04-09T12:00:00-04:00` → D-1 단계 4 "내일 만나요" (12–2월은 EST −05:00, 3/14부터 EDT −04:00) |
| A3 | TV `tl` 패널, 폰 `tc` 칩, 환영 칩 — 위치·문구 |
| A4 | `?phase=live` → 로드 안 됨 (흔적 0) |
| A5 | 레이아웃: 폰 칩이 레벨 패널·⛶ 버튼과 겹치지 않음 (phoneSE·가로) |
| A6 | perf: 소품 추가 후 TV fps 하락 < 5% |

## 8. 수동 QA
폰으로 마을 구경 (세로·가로), 노트북 1080p, 밤 시간대(19시 이후) 한 번.

## 9. 롤백
끄면 공사 소품·칩 사라짐. 데이터 없음.

## 10. 구현 기록 (2026-10-08, `wp/03-dday`)
- 파일: `features/dday/` — `index.js`(카운트다운 · 하객 환영 칩 · 마을 소품/HUD) · `i18n.js` · `style.css`.
- HUD: 터치 기기(폰)면 `tc` 칩, 아니면(TV·노트북) `tl` 패널 — 노트북에서 `?me=`로 연 경우도 패널.
- 소품 자리(월드 px): 표지판 (178,64) 34×24 · 공사 중 (100,64) 38×22 · 비계 (192,18)/(290,18) · 상자 (22,68)(36,72)(142,68) · 사다리 (280,30) · 화분 카펫 양옆 x 212/274 · 현수막 (122,118) · 깃발 줄 광장 위 y≈146 (overhead).
- 문서 표 밖 문구: `dday_chip_tomorrow` "내일 만나요! 🎉 · 입주민 {r}명" / "See you tomorrow! 🎉 · {r} residents", `dday_welcome_tomorrow` "💒 내일 만나요! 🎉" / "💒 See you tomorrow! 🎉".
- 남은 날 n은 문서 식 그대로 `ceil((liveStart − now) / 1일)` — liveStart가 당일 06:00이라 숫자는 매일 **오전 6시**에 줄어듦 (자정 아님).
- 시험 훅: HUD 요소의 `data-stage` · `data-n` · `data-props`(이 단계 소품 이름들). 시험은 월드 캔버스 픽셀 색으로 소품이 실제로 그려졌는지도 확인.
- 시험: `tests/features/dday.mjs` (82 체크, `slow`) — Playwright `clock.setFixedTime`(현지 정오) · `clock.install` + `fastForward`(10분 재계산 · 06:00 페이즈 전환).
