## Sonnet 질문

### S-001 · WP-00b · 꺼진 뒤에 도착하는 비동기 결과 — 기능이 "아직 켜져 있나"를 물을 방법이 없음          상태: open
- 상황: 로더(`core/features.js`)의 dispose 를 시험하다가 발견. 기능 코드가 `const d = await ctx.db.doc(p).get(); parent.append(ctx.el(…))` 처럼 `await` 뒤에서 DOM 을 만들면, 그 사이 기능이 꺼진 경우(관리자가 끔 · 페이즈 변경 · 서킷 브레이커)에도 노드가 붙고, dispose 는 이미 끝났으므로 다음 dispose 까지 남음 = "끄면 흔적 0"(02 §3 규칙 3) 위반. 이미 진행 중이던 `ctx.db` 호출은 꺼진 뒤에도 값을 돌려줍니다.
- 막힌 이유: 02 §3 규칙 3 은 "ctx로 등록한 모든 것"만 자동 정리를 약속하고, 02 §4 의 ctx 에는 "아직 켜져 있나?"를 묻는 방법이 없음 (`scope.alive()` 는 페이지 API 전용). 지금의 우회 = 비동기 결과를 `ctx.guard(fn)` 으로 감싼 콜백에서 처리 (꺼진 뒤에는 불려도 아무 일 안 함) — 되지만 await 스타일 코드에서는 잊기 쉬움.
- 선택지: A) 계약에 `ctx.alive(): boolean` 추가 (켜져 있는 동안 true, dispose 시작 시 false) — 02 §4 한 줄 + 로더 한 줄 + 시험. 기존 호출은 그대로 동작. / B) 지금 방식 유지 (02 §4 구현 메모의 `ctx.guard` 안내만) — 기능 시험의 S1(꺼진 뒤 흔적 0)이 놓친 것을 잡아냄.
- 제안: A — 한 줄 추가로 await 스타일 기능 코드가 안전해지고, 모든 기능 WP(특히 06 translate · 10 poll · 12 fourcut)에 같은 주의를 반복해서 적을 필요가 없음.
- 임시 처리: 02 §4 구현 메모에 `ctx.guard` 안내만 적었고 `ctx.alive()` 는 만들지 않음. 승인되면 로더 + 02 §4 + `core-units-loader` 에 한 곳씩 추가.
