# 06 · 결혼식 당일 런북 (운영 · 비상 절차)

> 대상: Patrick · 선경 · 당일 도우미 1–2명. 리허설 2(3월)에서 이 순서대로 한 번 통으로 해 봅니다.
> 기능별 세부 사용법은 `docs/guide/<기능>.md`.

## 1. 역할

| 역할 | 누구 | 하는 일 | 기기 |
|---|---|---|---|
| 라이브 도우미 | 사회자 옆 친구 1명 | 식순 "다음 ▶", 조용 모드, 투표 열고 닫기, 이벤트 버튼 | 관리자 로그인된 폰 또는 노트북 (`admin.html`) |

| 키오스크 담당 | 입구 안내 | 어르신 체크인·작성 도와드리기 | iPad (`kiosk.html`) |

## 2. 일정별 체크리스트

### D-30 (3월 둘째 주)
- [ ] 입구 체크인 포스터 QR 인쇄: `https://<사이트>/index.html#checkin` (WP-01)
- [ ] 테이블 카드 QR 인쇄: `https://<사이트>/index.html#snap` (사진 올리기 바로가기, v3.2)
- [ ] ⚙️ 설정: 결혼식 때 켤 기능 목록 확정 → 캡처해서 보관
- [ ] 매니페스트에서 **prereg `status: 'ready'`** 확인 (리허설 1 통과 후 Patrick이 변경 — TV가 설정을 늦게 받아도 출석 필터가 켜진 채로 시작, 02 §2.1)
- [ ] 식순(WP-05) 최종본 입력, 투표 질문(WP-10) 미리 만들어 두기 (닫힌 상태) — 관리자 페이지는 결혼식 전에도 이 탭들이 열림

### D-1 (식장 세팅)
- [ ] TV 노트북: Chrome 최신 · 전원 연결 · 절전/화면보호기 끔 · 알림 끔 · 해상도 1920×1080 · 브라우저 확대 100%
- [ ] 식장 와이파이 연결 + **휴대폰 핫스팟 예비** (비밀번호 메모)
- [ ] 번역(WP-06) 준비 — D-1은 아직 `pre`라서 TV에 번역 기능이 안 뜹니다. 그래서 TV 노트북에서 **`village.html?tv=1&phase=live`** 열기 →
      화면 한 번 클릭 → 모델 다운로드(처음이면 수 분) → 티커 둘째 줄에 🌐 번역이 나오는지 확인. 모델은 브라우저에 남아 당일 다시 받지 않음
- [ ] 확인이 끝나면 **`village.html?tv=1&phase=auto`**로 다시 열기 (`?phase=`는 그 탭에 기억되므로 반드시 auto로 해제) → 화면 한 번 클릭 → `F` 전체화면.
      당일 06:00에 페이즈가 자동으로 `live`가 됨
- [ ] 관리자 노트북: 🌐 번역 탭 → "🤖 빈 번역 모두 채우기" (저장본이 있으면 TV는 즉석 번역 없이 바로 표시)
- [ ] BGM(WP-07): **꺼짐** 확인 (식장 음향 사용)
- [ ] iPad 키오스크: `kiosk.html` → 사용법 고정(Guided Access) · 밝기 · 충전기
- [ ] 테스트 하객 1명 작성 → TV 입장 확인 → 관리자에서 삭제
- [ ] 🛡 본식 안전 모드 켰다 끄기 1번 (TV에서 기능이 사라졌다 돌아오는지)

## 3. 비상 절차 (위에서부터)

| 증상 | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| 특정 기능이 이상함 (겹침·오류·이상한 연출) | ⚙️ 설정에서 **그 기능만 끄기** (1초 안에 모든 기기 반영) | – | 결혼식 후 원인 수정 |
| 뭐가 문제인지 모르겠음 | 상단 **🛡 본식 안전 모드** (필수 기능만 남김) | TV `F5` 새로고침 → 화면 클릭 → `F` | – |
| TV 화면 멈춤/검은 화면 | `F5` 새로고침 → 클릭 → `F` | 노트북 재부팅 → `village.html?tv=1` | 백업 노트북으로 교체 |
| 와이파이 끊김 | 기다림: 마을은 계속 움직이고, 하객 글은 폰에 보관됐다가 자동 전송 | 노트북·키오스크를 핫스팟에 연결 | – |
| TV 상단 "연결이 불안정해요"가 계속 | 핫스팟으로 전환 | – | – |
| 체크인했는데 TV에 안 나옴 | 관리자 🎟 체크인 탭에서 이름 찾아 "수동 체크인" | prereg 기능 끄기 (→ 사전 입주자 **전원**이 마을에 보임, 연출만 줄어듦) | – |
| 페이즈가 이상함 (live가 아님) | ⚙️ 설정 → 페이즈 강제 `live` | – | 끝나면 `auto`로 되돌리기 |
| 오래된 화면이 계속 뜸 (오프라인 기능 의심) | 그 기기에서 주소 뒤에 `?nosw=1` 붙여 열기 (WP-13) | ⚙️ 설정에서 offline 끄기 | 런북 §5 킬스위치 배포 |
| Firestore 무료 한도 초과 (쓰기/읽기 실패 증가) | 당황하지 않기: TV는 마지막 상태로 계속, 하객 글은 기기에 보관 | 폰 마을 체크인 구독 끄기 등 03 §7 손잡이 | 한도는 매일 자정(미국 태평양 시각)에 초기화 |

원칙: **결혼식 중에는 코드를 고치거나 배포하지 않습니다.** 끄기 → 안전 모드 → 새로고침까지만.

## 4. 기능을 끄면 어떻게 되나 (당일 판단용)

| 기능 | 끄면 |
|---|---|
| prereg | 체크인 연출 없음. 사전 입주자 전원이 마을에 보임 (출석 필터 해제). 새 하객 작성은 그대로 |
| couple | 신랑·신부가 기본 캐릭터로 |
| live | 식순 연출·큐 제목·자동 조용 모드 없음. **조용 모드 버튼(코어)은 그대로** 쓸 수 있음 |
| translate | 티커 번역 줄 없음 |
| bgm | 음악·효과음 없음 (코어 차임은 M 키) |
| meter | 온도계 없음 |
| bingo / poll | 하객 폰의 해당 카드 사라짐. 이미 저장된 기록은 남음 |
| card / fourcut | 해당 버튼 사라짐 |
| offline | 서비스워커 해제 (다음 새로고침부터 일반 웹페이지) |

## 5. 서비스워커 킬스위치 (WP-13 · 최후 수단)

오프라인 기능의 서비스워커가 잘못되어 **모든 기기에서 옛 화면**이 계속 뜨는 경우에만:
1. 저장소의 `tools/sw-killswitch.js`를 `public/sw.js`로 복사 (덮어쓰기)
2. Netlify에 `public` 폴더 다시 배포
3. 각 기기에서 페이지를 두 번 새로고침 → 서비스워커가 스스로 해제되고 캐시를 지움
(이 파일은 WP-13이 만들고 테스트합니다. `public/_headers`가 `sw.js`를 `Cache-Control: no-cache`로 내보내므로 브라우저가 새 sw.js를 바로 확인합니다 —
드래그 배포에서도 적용되도록 헤더는 `netlify.toml`이 아니라 `public/_headers`에 있습니다.)
